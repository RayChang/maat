## 1. 起點與範圍

目前 repository 只有設計與研究文件，已有 Git 追蹤紀錄。舊計畫（已移除）曾引用的 scanner、HTML 原型、skill 副本及 CI workflow 不在目前工作目錄；不得假設它們存在，也不建立假的相容性要求。

本計畫實作唯讀診斷 CLI、診斷 Skill 與經明確核准可修改的改善 Skill，命令執行另依授權。兩種 Skill 與範本的交接依[運作架構](../specs/2026-11-04-toolkit-operation-architecture.md)；R-D5 已核准 A：程式化 reducer／guards／ledger 控制工具內流程，host 執行核准動作。

不實作 CLI 寫檔式 init／apply、自動 executor／loop runner、遠端證據擷取或模型 API 呼叫。若後續選 C，需先明確修訂這個邊界及相依計畫。

技術起點沿用舊計畫的 Python 3.11+、標準函式庫 `unittest`；只有解析實際支援格式需要時才宣告依賴。確切 CLI 命令、政策格式與套件布局在階段 2 定版，不先替不存在的舊程式保留命令介面。

## 2. 階段與相依

| 階段 | 工作 | 前置 |
|---|---|---|
| 1 | 整合 catalog 與來源對照 | 正式 spec |
| 2 | 定版標準／證據／範本／流程資料模型、CLI／政策介面與核心測試 | 階段 1 的逐題契約已審閱；controller 依已核准 A 設計 |

每階段先寫可失敗的測試，再實作，再跑最小相關測試。未解決的 Loop 決定不阻止基礎 discovery，但阻止把相應提案編入已生效的檢查政策。

## 4. 階段 2：資料與介面契約

建議模組責任為 catalog、models、profile、discovery、adapters、detectors、evaluation、report、plan 與 CLI；實作可合併小模組，不為每個名詞強制建立檔案。

範本、改善核准與執行授權的資料責任已明列於運作架構。依已核准 A 納入 reducer／guards 與持久 workflow records，與 host executor 分開；現階段是設計，不宣稱模組已實作。

- [ ] 定版 schema／catalog／detector／adapter 的版本與相容規則。
- [ ] 建立 typed models，區分單題結果、逐層狀態、形式、證據等級、證據來源及適用性。
- [ ] 定義機器觀察、agent 候選、使用者確認的獨立欄位與有效性判斷。
- [ ] 定義草案／已核准政策的診斷及 authoritative 結果邊界，不新增 D2 層級枚舉或套用候選門檻。
- [ ] 定義政策檔與明確輸入方式；無政策仍可掃描，未知選項不靜默猜測。
- [ ] 定版 CLI 的掃描、讀取確認資料、選擇改善目標與輸出計畫介面；v1 不提供 apply。
- [ ] 定義範本與引用版本、修改核准／執行授權、相關材料 checkpoint，以及每份計畫的動作／修正／停止條件。
- [ ] 定義 exit code，區分命令／資料錯誤與正常完成但有缺口；不得用退出成功代表所有規範都已達標。
- [ ] 決定最低 Python／CLI 版本及作業系統測試矩陣，記入正式 spec。

**測試：** 缺少必填資訊、重複 ID、非法枚舉、引用失效、循環相依、版本不相容、到期與指紋失效的人工確認。

## 5. 階段 3：安全掃描與 CLI adapter

- [ ] 建立有範圍的本機檔案 inventory，不追蹤越界 symlink、不讀個人憑證、不聯網、不執行專案程式。
- [ ] 保存已搜尋路徑與排除範圍；讀取失敗回傳診斷與 unknown，不靜默略過。
- [ ] 分別查核 Claude Code CLI、OpenAI Codex CLI、GitHub Copilot CLI 的官方文件，記錄版本、日期與來源。
- [ ] 以有限清單實作指令、skills、hooks、權限設定面的辨識；每個設定面各自標示支援程度。
- [ ] 分別測試各家載入／優先順序，不把相同檔名解讀為相同語意。
- [ ] 未選擇目標 CLI 時只列發現，不強迫補所有 vendor 檔案。
- [ ] 組織／使用者設定、trust 與實際 session 載入結果無法觀察時明列 unknown。

**測試：** 每家 CLI 的最小正例、缺檔、解析錯誤、覆寫／遮蔽、未知版本、混用設定、越界與不完整搜尋。不要拿 IDE 或雲端文件作為 CLI fixture 的唯一依據。

## 6. 階段 4：Detectors 與評估

- [ ] 依階段 1 凍結的清單實作 deterministic detectors；每個回傳證據、版本、scope 與診斷。
- [ ] 「有設定」只證明設定；未知格式與動態 shell 語意不以字串猜測為成功。
- [ ] 將 D8 的人與 agent 評估並列輸入，不修改原始機器觀察。
- [ ] Agent 候選不能單獨滿足必要條件；人工確認須符合該題證據要求。
- [ ] 實作逐層狀態，對未確認適用性、缺少證據與不適用分開呈現。
- [ ] 從能力相依產生缺口；設定訊號不當作實際使用證據。

**測試：** 每題正反案例、partial／unknown／not_applicable、設定存在但未生效、人工與機器衝突、只有模型聲稱通過、空題庫不得 adopted、必要條件未知不能 ready。

## 7. 階段 5：報告與改善計畫

- [ ] 同一資料模型產生穩定 JSON 與 Markdown，不維護兩套判定。
- [ ] 輸出版本、目標 CLI、scope、單題證據、各來源評估、缺口、逐層狀態與限制。
- [ ] 依目標與相依排序改善步驟；每步提供規則卡版本、目標位置、風險、核准要求與驗收方式。
- [ ] 遇到未知測試指令或位置時產生待確認動作，不猜測或執行指令。
- [ ] 對新專案輸出最小起步計畫，不寫入指引、政策或 vendor 設定。
- [ ] 範本選擇保留規則卡／check／版本引用、可支持與不可證明的主張；render 未填值或版本未核對不能直接套用。
- [ ] 結果預設 stdout 或使用者明確指定的報告位置；不自動污染目標 repository。

**測試：** JSON／Markdown 一致、固定排序、來源分欄、包含未完成原因、相依順序、stale 證據指紋、沒有總分，以及每步有明確驗收。

## 8. 階段 6：兩種 Skill、改善核准與 Loop

- [ ] 診斷 Skill 負責唯讀 CLI、內容準則、候選及有效確認；按三家 CLI 實際能力分發。
- [ ] 改善 Skill 依報告選用資源、展示有限計畫、取得核准，交既有 agent 修改；命令執行另依授權，不啟動 agent／自動 runner。
- [ ] 同一計畫可描述有限修正或逐候選核准，沒有明示條件不能默認無限續行。
- [ ] 改善後按本題契約重驗，不因模板安裝而通過，也不對所有宣告題要求執行證據。
- [ ] 依 A 實作兩種 Loop 的執行綁定，測試 reducer／guards、持久計數、checkpoint、並行衝突與恢復，明示不能阻止 host 繞過。
- [ ] 不讓兩種 Skill 自行重新定義通過條件；依標準規則與有效證據評估。
- [ ] 說明資料保存、證據邊界、未知與不適用，提供「新專案起步」與「擴充 Loop 前缺口」範例。
- [ ] 更新 README 與使用說明，標示哪些功能仍是後續版本，不憑空建立舊計畫宣稱存在的多份 skill 副本。

**測試：** 說明與已核准 catalog／CLI 契約一致；診斷不改專案，改善只執行核准修改且執行驗證另授權。覆蓋空模板、無新證據、失效核准、預期修改與非預期漂移、人工驗收及 host 繞過的聲明限制；不宣稱跨產品介面一體支援。

## 9. 階段 7：端到端驗收

- [ ] 新專案 fixture：沒有政策或 agent 設定，仍產生可用報告與起步計畫。
- [ ] 既有專案 fixture：測試與 CI 存在，但沒有執行證據，不能宣稱生效。
- [ ] 漸進 fixture：有明確能力缺口，能列出採用目標所需步驟與順序。
- [ ] D8 fixture：機器、agent、使用者三者並列；失效確認與衝突不被當成通過。
- [ ] 三家 CLI fixtures：同一 repository 可得到不同 adapter 解讀與限制。
- [ ] 安全 fixture：惡意設定、越界 symlink、無權讀取與錯誤格式不導致命令執行或成功形狀的 fallback。
- [ ] 對掃描與規劃前後的目標 fixture 做內容比對，確認零修改，並驗證沒有 network／target subprocess。
- [ ] 改善 fixture：未核准不改、核准後僅動範圍內內容，命令未授權不執行，無關 dirty work 保留。
- [ ] 內容走查 fixture：`prompt.task-spec` 的空模板不能通過，有效材料及人工確認才能完成本題，未核准政策不能發正式層級認定。
- [ ] 按選定 controller 的實際邊界驗收兩種 Loop；不能以文檔或 Skill 指示代替程式化守門測試。
- [ ] 測試套件建立後執行 `python3 -m unittest discover -s tests -v`，再做 CLI smoke test。

目前尚無程式與測試套件，不把上述命令記為本次已執行或已通過。
